## 1. System Architecture Overview

WAPCentral operates on a unified Google Cloud Platform (GCP) and Firebase infrastructure:

- **Google Cloud Project:** `wapcentral-prod`
- **Primary Region:** `us-central1`
- **Frontend Dashboard:** [https://central.webappypie.com](https://central.webappypie.com) (Firebase
  Hosting with multi-region CDN)
- **Backend Microservices:** Google Cloud Run (Serverless, auto-scaling, zero-downtime rolling
  updates)
  - Admin API: `admin.central.webappypie.com` (Port 8080)
  - Promotion Delivery API: `promo.central.webappypie.com` (Port 8081)
  - AI Gateway: `ai.central.webappypie.com` (Port 8082)
  - Background Workers: `workers.central.webappypie.com` (Port 8083)
- **Primary Database:** Google Cloud Firestore (Native mode, 18 partitioned collections, 100%
  audited security rules)
- **Object Storage:** Google Cloud Storage (`wapcentral-prod.firebasestorage.app` &
  `wapcentral-firestore-backups-prod`)
- **Key & Secret Management:** Google Cloud Secret Manager

## 4. Custom Domain Setup (`central.webappypie.com`)

Firebase Hosting provides zero-configuration SSL termination and HTTP/2 distribution.

### Step 1: Add Custom Domain in Firebase

```bash
firebase hosting:sites:create wapcentral-prod --project=wapcentral-prod
firebase target:apply hosting app wapcentral-prod
```

In the Firebase Console under **Hosting → Custom Domains**, add `central.webappypie.com`.

### Step 2: Configure DNS Records

Add the DNS records generated by Firebase Hosting at your DNS provider (e.g. Cloudflare / Route53):

| Type  | Host      | Value / Target                         | TTL        |
| ----- | --------- | -------------------------------------- | ---------- |
| `A`   | `central` | `199.36.158.100`                       | Auto / 300 |
| `TXT` | `central` | `hosted-domain-verify=wapcentral-prod` | Auto / 300 |

### Step 3: SSL Provisioning

Firebase Hosting automatically provisions and renews a Let's Encrypt / Google Trust Services SSL
certificate within 15–30 minutes of DNS verification.

## 5. Secret Manager Configuration

All confidential keys must reside exclusively in Google Cloud Secret Manager with strict access
control:

```bash
# OpenAI API Key
echo -n "sk-prod-openai-..." | gcloud secrets create OPENAI_API_KEY --data-file=- --project=wapcentral-prod

# Gemini API Key
echo -n "AIzaSy..." | gcloud secrets create GEMINI_API_KEY --data-file=- --project=wapcentral-prod

# Anthropic API Key
echo -n "sk-ant-..." | gcloud secrets create ANTHROPIC_API_KEY --data-file=- --project=wapcentral-prod

# Promotion Signing Secret
openssl rand -hex 32 | tr -d '\n' | gcloud secrets create PROMOTION_SIGNING_SECRET --data-file=- --project=wapcentral-prod
```

Configure GitHub Secrets for the CI/CD Pipeline:

- `GCP_SA_KEY_PROD`: Service account key with Cloud Run Admin, Storage Admin, and Artifact Registry
  Writer roles.
- `FIREBASE_SERVICE_ACCOUNT_WAPCENTRAL_PROD`: Service account key with Firebase Hosting Admin role.

Before triggering a production release:

1. **Local Test Suite:**
   ```bash
   pnpm test
   pnpm test:rules
   ```
2. **Build Verification:**
   ```bash
   pnpm build
   ```

   ```bash

   pnpm lint
   ```

   ensuring `projectId` is `wapcentral-prod` and `emulator: false`.

## 7. Deployment Execution

### Automated Continuous Deployment

Every push or merge to the `main` branch triggers the GitHub Actions workflow defined in
`.github/workflows/deploy.yml`:

1. **Stage 1 (Quality Gate):** Runs TypeScript type-checks, ESLint, Prettier, unit tests, and
   Firestore emulator penetration tests.
2. **Stage 2 (Hosting Deploy):** Builds React Admin Dashboard and publishes to Firebase Hosting.
3. **Stage 3 (Cloud Run Deploy):** Builds Docker images via Cloud Build, registers them in Artifact
   Registry, and deploys with `--traffic=100` zero-downtime rolling updates.
4. **Stage 4 (Database Deploy):** Deploys Firestore composite indexes, security rules, Storage
   rules, and Remote Config parameters.
5. **Stage 5 (Post-Deploy Smoke Test):** Executes end-to-end synthetic probe tests verifying live
   health endpoints and security headers.

### Manual Workflow Dispatch

To trigger manually from the GitHub UI:

1. Navigate to **Actions** → **Production Deployment Pipeline**.
2. Click **Run workflow**, select branch `main`, target `production`.

## 9. Ongoing Operations & Monitoring

### Automated Firestore Backups

- Executes daily at `02:00 UTC` via Cloud Scheduler job `firestore-daily-backup`.
- Stored in bucket: `gs://wapcentral-firestore-backups-prod/exports/`.
- Lifecycle rules automatically transition objects to Nearline (7 days) and Coldline (30 days).

### Uptime Probes & Alerting

- Synthetics monitor `central.webappypie.com` and all microservices across USA, Europe, and Asia
  Pacific edge locations.
- Any downtime exceeding 120 seconds triggers automated alerts to PagerDuty and Slack
  `#wapcentral-incidents`.
